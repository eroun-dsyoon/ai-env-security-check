# 기업 AI 사용환경 보안 체크 도구

회사에서 쓰는 모든 AI 환경을 찾아 점검하고, 우리 회사에 어떤 보안위협이 있는지 검토하는 자기진단 도구입니다.
점검이 끝나면 위험 순위, 부족한 보안기술, 개선 로드맵을 담은 종합 리포트가 나옵니다.

**바로 사용하기 →** https://eroun-dsyoon.github.io/ai-env-security-check/

## 무엇을 점검하나요

| 단계 | 내용 |
|---|---|
| 1. 환경 발굴 | 7개 범주 30종 AI 환경 중 회사에서 쓰는 것을 모두 선택합니다. 목록에 없는 사내 시스템은 직접 추가합니다. |
| 2. 전사 공통 통제 | 정책·계약·교육·사고 대응처럼 환경과 무관하게 한 번만 확인하는 14개 항목을 점검합니다. |
| 3. 환경별 점검 | 환경마다 담당 관리자가 프로파일 4문항, 통제 항목, 정보보안 이슈를 확인합니다. |
| 4. 보안기술 점검 | 선택한 환경에 필요한 보안기술·제품군(26종 중 해당 항목)의 보유 여부를 확인합니다. |
| 5. 종합 리포트 | 환경별 위험 매트릭스, 조직 종합 점수, 이슈 목록, 부족한 보안기술 추천, 30/60/90일 로드맵을 보여 줍니다. |

점검 범주는 다음 7개입니다.

- 개발·코딩 (IDE 어시스턴트, CLI·자율 코딩 에이전트, 코드 인덱싱·리뷰 AI)
- 업무용 웹 AI (범용 챗봇, AI 검색, 문서·번역, 이미지 생성, 회의록 AI, AI 브라우저)
- 내부 시스템 연동 (RAG 지식검색, 업무 자동화, 배치 파이프라인, 그룹웨어 AI, AI 에이전트·MCP 연동)
- 업무 도구 내장 (M365 Copilot·Workspace Gemini, 협업툴 AI, CRM·ERP AI, HR·채용 AI)
- 고객 대면 (대외 서비스 내 AI 기능, 고객 상담 챗봇, 마케팅 콘텐츠 생성)
- 인프라·플랫폼 (클라우드 AI 플랫폼, 자체 호스팅 모델, AI 게이트웨이, 모델 학습·파인튜닝)
- 그림자 AI (부서 단위 비인가 구독, 개인 계정 사용, 브라우저 확장·앱)

전문 용어 옆의 **?** 버튼을 누르면 설명이 나옵니다. 상단 **용어 사전**에서 전체 용어를 검색할 수 있습니다.

## 데이터 처리

- 입력한 응답은 사용자의 브라우저 저장소(localStorage)에만 저장됩니다.
- 서버로 전송하는 기능이 없고, 외부 스크립트·폰트를 불러오지 않습니다.
- 결과는 JSON 파일(다시 불러오기용)과 HTML 리포트로 사용자 PC에 저장할 수 있습니다.
- 인터넷이 차단된 환경에서는 `index.html` 파일 하나를 내려받아 브라우저로 열면 됩니다.

## 점수 산출 방식

| 구성 | 산출 |
|---|---|
| 환경 잠재위험 | 환경 유형의 구조적 위험도(45%)와 프로파일 4문항(55%)으로 계산합니다. |
| 환경 잔여위험 | 잠재위험 × (1 − 통제율 × 0.9) × (1 + 필수 통제 미달률 × 0.5). 필수 항목 미비 1개당 6점의 하한을 둡니다. |
| 이슈 가산 | 체크한 이슈의 심각도 합계입니다(치명 5·중대 3·경미 1점, 최대 20점). |
| 조직 종합점수 | 환경 위험점수를 노출 가중치(사용자 범위·데이터 등급)로 가중 평균하고, 전사 공통 통제 미비분(최대 15점)을 더합니다. |
| 보안기술 확보율 | 필요한 보안기술 중 보유 비율입니다(필수 2배·권장 1배 가중). 위험 점수와 별도로 표시합니다. |

점수는 절대 등급이 아니라 우선순위를 정하는 도구입니다.

## 조직에 맞게 수정하기

점검 항목과 가중치는 `src/` 폴더의 데이터 파일에 있습니다.

| 파일 | 내용 |
|---|---|
| `src/p3_data.js` | 환경 유형(`ENV_TYPES`), 프로파일 문항, 공통 통제, 환경별 통제(`CTRL_GROUPS`), 이슈(`ISSUES`) |
| `src/p3b_tech.js` | 보안기술 카탈로그(`TECH`)와 용어 사전(`GLOSSARY`) |

수정한 뒤 다음 명령으로 `index.html`을 다시 만듭니다. Node.js 18 이상이 필요합니다.

```bash
node build.mjs
```
